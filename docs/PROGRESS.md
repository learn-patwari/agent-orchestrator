- Roles: `developer` and `reviewer` are replaced by `developer_1` and `developer_2` (they peer review each other, then the architect reviews). - Release stages (2026-11-08): tasks now have an owner (developer_1 or developer_2) and the other one peer reviews. After peer approval the task goes architect review, deploy to QC, QC result, request production, human AND architect approval, deployed to production (`backend/app/pipeline/release.py`, endpoints under `/api/pipeline/tasks/{id}/`). Each step is refused out of order and records a real hand-off (`pipeline/handoffs.py`). A QC or architect failure returns the task to its owning developer. `/api/office` also returns `environments` (QC and PROD versions) and `pending_prod`. The Agents page shows an "Approve production deploy" banner and the QC/PROD racks light up with a version only when something is deployed. 229 tests pass; checked in the browser against the real API.
- Not yet: nothing drives these endpoints automatically (the developer, architect, tester and CI/CD agents do not call them yet; today they are called by the API or the pipeline page), L1 to L4 levels, the incident reporter trigger, and a live-model run of the whole cycle. Deployment itself stays an in-app plugin built only when asked, so "deploy" only records what the app was told.
